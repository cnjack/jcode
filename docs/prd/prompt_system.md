# 提示系统增强 — 产品需求文档 (PRD)

## 1. 背景与目标

### 1.1 背景

jcode 当前的提示系统基于 Go `text/template` 静态渲染，存在以下局限：

- **无上下文压缩**：长对话中 token 耗尽后只能警告，无法自动摘要续航
- **单文件内存**：仅支持项目根目录 `AGENTS.md` 单文件注入，无法分层管理全局/项目/本地配置
- **无缓存策略**：每次生成系统提示均为完整重建，静态内容无法跨会话复用
- **同步加载**：环境信息（Git 状态、目录树等）串行获取，首次响应延迟较高
- **无跨文件引用**：`AGENTS.md` 不支持引用外部文件，大型项目难以模块化组织指令

### 1.2 目标

在保持 Go 实现简洁性的前提下，面向实际使用痛点进行渐进式增强：

| 目标 | 衡量标准 |
|------|---------|
| 长对话可持续性 | token 达到 85% 时自动压缩，对话可延续 ≥2 轮 |
| 多层次配置 | 支持全局 `~/.jcoding/AGENTS.md` + 项目 + 本地三级加载 |
| 首次响应加速 | 系统提示生成耗时降低 ≥30% |
| 指令模块化 | 支持 `@include` 引用外部文件 |
| 缓存复用 | 静态提示块跨会话复用，减少重复 token 消耗 |

## 2. 用户故事

### US-1: 自动上下文压缩
> **作为**一个在长对话中重构大型代码库的开发者，  
> **我希望**当 token 接近上限时系统自动摘要历史对话，  
> **以便**我可以继续当前任务而无需手动开启新会话。

**验收标准**：
- token 使用达到可配置阈值（默认 85%）时触发自动压缩
- 压缩后保留：用户原始请求、关键文件路径、已完成/待执行步骤、最近错误与修复
- 压缩过程对用户透明，TUI 显示 "正在压缩上下文..." 状态
- 连续 3 次压缩失败后停止自动压缩（断路器）

### US-2: 多层次内存配置
> **作为**一个同时维护多个项目的开发者，  
> **我希望**在全局、项目、本地三个层级维护 AGENTS.md，  
> **以便**通用规则全局生效，项目特定规则不污染其他项目。

**验收标准**：
- 加载顺序：全局 `~/.jcoding/AGENTS.md` → 项目根目录 `AGENTS.md` → 本地 `AGENTS.local.md`
- 内容合并（非覆盖），后加载的层级追加在前一层级之后
- 总内容不超过 40,000 字符，超出时截断并警告

### US-3: @include 指令
> **作为**一个大型 monorepo 的维护者，  
> **我希望**在 AGENTS.md 中引用子目录下的指令文件，  
> **以便**模块化组织不同子项目的 agent 规则。

**验收标准**：
- 语法：`@include path/to/file.md`（相对于当前文件所在目录）
- 支持嵌套引用（最大深度 5 层）
- 循环引用检测并跳过，输出警告日志
- 文件不存在时跳过并输出警告日志，不阻断加载

### US-4: 提示分块缓存
> **作为**一个频繁切换会话的开发者，  
> **我希望**静态系统提示部分能跨会话复用，  
> **以便**减少每次对话的 token 开销。

**验收标准**：
- 系统提示拆分为静态块（规则、工具描述）和动态块（环境信息、Git 状态）
- 支持 API 层面的 cache_control 标记（当模型 API 支持时）
- 缓存粒度可配置，支持禁用

### US-5: 异步环境加载
> **作为**一个在低速网络连接远程环境的开发者，  
> **我希望**Git 状态、目录树等信息并行获取，  
> **以便**减少系统提示的生成等待时间。

**验收标准**：
- Git 分支、dirty 状态、最后提交、项目类型、目录树并行获取
- 单项超时 3 秒，超时项跳过并使用空值
- 总体加载时间 ≤ max(所有子任务) + 100ms 开销

## 3. 功能需求

### P0 — 必须实现（核心体验）

| ID | 功能 | 描述 |
|----|------|------|
| F-01 | 自动上下文压缩 | token 达阈值时调用 LLM 生成对话摘要，替换历史消息 |
| F-02 | 压缩断路器 | 连续 N 次压缩失败后停止，防止无限循环 |
| F-03 | 多层次 AGENTS.md | 全局/项目/本地三级加载与合并 |
| F-04 | @include 指令 | 文件引用解析、嵌套支持、循环检测 |

### P1 — 应该实现（性能优化）

| ID | 功能 | 描述 |
|----|------|------|
| F-05 | 异步环境加载 | 并行获取 Git/目录树/项目类型，超时降级 |
| F-06 | 提示分块缓存 | 静态/动态分离，支持 cache_control 标记 |
| F-07 | 压缩提示模板 | 可自定义的压缩指令模板，控制摘要保留内容 |

### P2 — 可以实现（体验增强）

| ID | 功能 | 描述 |
|----|------|------|
| F-08 | 压缩 TUI 反馈 | 压缩进行中在状态栏显示进度 |
| F-09 | 内存字符数统计 | 加载 AGENTS.md 后在 debug 日志中输出各层级字符数 |
| F-10 | 手动压缩命令 | 用户可通过 `/compact` 命令主动触发上下文压缩 |

---

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| **性能** | 系统提示生成 ≤ 200ms（异步加载后）；压缩操作不阻塞用户输入 |
| **可靠性** | 任何加载/解析失败降级为当前行为（静态模板），不影响基本功能 |
| **兼容性** | 不依赖特定 LLM provider API；cache_control 为可选增强 |
| **可配置性** | 压缩阈值、断路器次数、AGENTS.md 最大字符数通过 config.json 可调 |
| **测试** | 每个新增模块 ≥80% 单元测试覆盖；压缩摘要质量需人工评审 |
| **日志** | 压缩触发/成功/失败、include 解析、缓存命中率记录到 debug.log |

---

## 5. 成功指标

| 指标 | 基线 (当前) | 目标 | 度量方式 |
|------|-----------|------|---------|
| 长对话存活轮次 | token 耗尽即终止 | 自动压缩后延续 ≥2 轮 | 会话 JSONL 中压缩事件后的对话轮次 |
| 系统提示生成耗时 | ~150ms (串行) | ≤100ms (并行) | debug.log 计时 |
| AGENTS.md 加载层级 | 1 级（项目） | 3 级（全局/项目/本地） | 功能测试 |
| 压缩失败率 | N/A | ≤ 10%（断路器保护） | debug.log 失败事件统计 |
| 用户手动新建会话频率 | 频繁（token 耗尽） | 下降 ≥50% | 用户反馈 / 会话长度统计 |

---

## 6. 范围边界

### 本期包含
- 上下文自动压缩（P0）
- 多层次 AGENTS.md（P0）
- @include 指令（P0）
- 异步环境加载（P1）
- 提示分块缓存（P1）

### 本期不包含
- 提示建议生成（Claude Code PromptSuggestion 功能，复杂度高，后期评估）
- 特征标志系统（当前功能规模不需要）
- Git 完整快照（增量 diff 对 Go CLI 场景收益有限）
- 多模型缓存策略差异化（先统一实现，后期按需扩展）

---

## 7. 依赖与风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 压缩摘要质量不可控 | 高 | 中 | 结构化压缩模板 + 保留用户原始消息要点 |
| LLM API 不支持 cache_control | 中 | 低 | 缓存标记为可选增强，不影响核心功能 |
| AGENTS.md 内容过大影响性能 | 低 | 中 | 40K 字符硬上限 + 按层级截断 |
| @include 循环引用 | 低 | 低 | 路径集合检测 + 最大深度限制 |
